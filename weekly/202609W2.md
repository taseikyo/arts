### 1. [3875.构造奇偶一致的数组I](https://leetcode.cn/problems/construct-uniform-parity-array-i/description/?envType=daily-question&envId=2026-09-02)

#### 3875-DESC

给你一个长度为 n 的数组 nums1，其中包含 互不相同 的整数。

你需要构造另一个长度为 n 的数组 nums2，使得 nums2 中的元素要么全部为 奇数，要么全部为 偶数。

对于每个下标 i，你必须从以下两种选择中 任选其一（顺序不限）：

> nums2[i] = nums1[i]
>
> nums2[i] = nums1[i] - nums1[j]，其中 j != i

如果能够构造出满足条件的数组，则返回 true；否则，返回 false。

示例 1：

> 输入： nums1 = [2,3]
>
> 输出： true
>
> 解释：
>
> 选择 nums2[0] = nums1[0] - nums1[1] = 2 - 3 = -1。
>
> 选择 nums2[1] = nums1[1] = 3。
>
> nums2 = [-1, 3]，两个元素均为奇数。因此答案为 true。

示例 2：

> 输入： nums1 = [4,6]
>
> 输出： true
>
> 解释：
>
> 选择 nums2[0] = nums1[0] = 4。
>
> 选择 nums2[1] = nums1[1] = 6。
>
> nums2 = [4, 6]，两个元素均为偶数。因此答案为 true。

提示：

- 1 <= n == nums1.length <= 100
- 1 <= nums1[i] <= 100
- nums1 中的所有整数互不相同。

### 1. [我是如何减少 70% GTA 线上模式的加载时间的](https://nee.lv/2021/02/28/How-I-cut-GTA-Online-loading-times-by-70)

> 发布时间：2021-02-28， [存档](../blog/2026/09/GTAOnlineLoading.md)
>
> 这是一篇老文章了，一直在收藏夹没看，整理文件夹正好看到，就看了下

- 现象：GTAOL线上模式加载极其缓慢，作者设备原版耗时6分钟，故事模式仅70秒。瓶颈不在磁盘、网络、显卡，而是CPU单线程被占满。
- 两个根因
	- JSON解析缺陷：解析10MB商店目录JSON，sscanf反复调用strlen重复计算字符串长度，造成大量CPU损耗。
	- 错误的数据存储逻辑：63000条商品存入数组时，每次插入都暴力全数组遍历做哈希去重，产生近20亿次无效对比；而原始JSON数据本身全部唯一，根本不需要去重。本该使用哈希表，却用数组线性查找。
- 验证手段：编写DLL注入补丁，一是缓存strlen计算结果；二是直接跳过去重逻辑。两项修改完成后加载时间降至1分50秒，提速约69.4%。
- 后续结果：文章爆火，R星注意到此问题，破例给予10000美元赏金，随后官方推送补丁彻底修复加载性能问题。
- 技术启示：即使文件体积不大，低效的字符串处理、O(n^2)复杂度的暴力遍历，也会带来灾难性性能；闭源软件可以通过栈采样、内存转储做逆向性能分析。
