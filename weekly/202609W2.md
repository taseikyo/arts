你需要构造另一个长度为 n 的数组 nums2，使得 nums2 中的元素要么全部为 奇数，要么全部为 偶数。

对于每个下标 i，你必须从以下两种选择中 任选其一（顺序不限）：

> nums2[i] = nums1[i]
>

> 选择 nums2[0] = nums1[0] = 4。
>
> 选择 nums2[1] = nums1[1] = 6。

> nums2 = [4, 6]，两个元素均为偶数。因此答案为 true。

#### 3876-CODE

```go
func uniformArray(nums1 []int) bool {
	// 只有一种情况是false -> 最小值是偶数 && 数组中出现了奇数
	// 其余情况都是true
	if slices.Min(nums1)%2 == 0 {
		for _, v := range nums1 {
			if v%2 != 0 {
				return false
			}
		}
	}

	return true
```

### 3. [3903.最小稳定下标I](https://leetcode.cn/problems/smallest-stable-index-i/description/?envType=daily-question&envId=2026-09-04)

#### 3903-DESC

给你一个长度为 n 的整数数组 nums 和一个整数 k。

对于每个下标 i，定义它的 不稳定值 为 max(nums[0..i]) - min(nums[i..n - 1])。

换句话说：

- max(nums[0..i]) 表示从下标 0 到下标 i 的元素中的 最大值 。
- min(nums[i..n - 1]) 表示从下标 i 到下标 n - 1 的元素中的 最小值 。

如果某个下标 i 的不稳定值 小于等于 k，则称该下标为 稳定下标 。

返回 最小 的稳定下标。如果不存在这样的下标，则返回 -1。

示例 1：

> 输入： nums = [5,0,1,4], k = 3
>
> 输出： 3
>
> 解释：
>
> 在下标 0 处：[5] 中的最大值是 5，[5, 0, 1, 4] 中的最小值是 0，因此不稳定值为 5 - 0 = 5。
>
> 在下标 1 处：[5, 0] 中的最大值是 5，[0, 1, 4] 中的最小值是 0，因此不稳定值为 5 - 0 = 5。
>
> 在下标 2 处：[5, 0, 1] 中的最大值是 5，[1, 4] 中的最小值是 1，因此不稳定值为 5 - 1 = 4。
>
> 在下标 3 处：[5, 0, 1, 4] 中的最大值是 5，[4] 中的最小值是 4，因此不稳定值为 5 - 4 = 1。
>
> 这是第一个不稳定值小于等于 k = 3 的下标，因此答案是 3。

示例 2：

> 输入： nums = [3,2,1], k = 1
>
> 输出： -1
>
> 解释：
>
> 在下标 0 处，不稳定值为 3 - 1 = 2。
>
> 在下标 1 处，不稳定值为 3 - 1 = 2。
>
> 在下标 2 处，不稳定值为 3 - 1 = 2。
>
> 这些值都不小于等于 k = 1，因此答案是 -1。

示例 3：

> 输入： nums = [0], k = 0
>
> 输出： 0
>
> 解释：
>
> 在下标 0 处，不稳定值为 0 - 0 = 0，它小于等于 k = 0。因此答案是 0。

提示：

- 1 <= nums.length <= 100
- 0 <= nums[i] <= 10^9
- 0 <= k <= 10^9

#### 3903-CODE

很简单的一道题，用三次遍历就能解决

```go
import "math"

func firstStableIndex(nums []int, k int) int {
	n := len(nums)
	maxNums, minNums := make([]int, n), make([]int, n)
	maxNums[0] = nums[0]
	minNums[n-1] = nums[n-1]
	for i := 1; i < n; i++ {
		maxNums[i] = maxNums[i-1]
		if nums[i] > maxNums[i-1] {
			maxNums[i] = nums[i]
		}
	}
	for i := n - 2; i >= 0; i-- {
		minNums[i] = minNums[i+1]
		if nums[i] < minNums[i+1] {
			minNums[i] = nums[i]
		}
	}

	res := math.MaxInt
	for i := 0; i < n; i++ {
		if maxNums[i]-minNums[i] > k {
			continue
		}
		if res > maxNums[i]-minNums[i] {
			return i
		}
	}

	return -1
}
```

### 4. [115.不同的子序列](https://leetcode.cn/problems/distinct-subsequences/description/?envType=daily-question&envId=2026-09-06)

#### 115-DESC

给你两个字符串 s 和 t ，统计并返回在 s 的 子序列 中 t 出现的个数。

测试用例保证结果在 32 位有符号整数范围内。

示例 1：

> 输入：s = "rabbbit", t = "rabbit"
>
> 输出：3
>
> 解释：
>
> 如下所示, 有 3 种可以从 s 中得到 "rabbit" 的方案。
>
> rabbbit
>
> rabbbit
>
> rabbbit

示例 2：

> 输入：s = "babgbag", t = "bag"
>
> 输出：5
>
> 解释：
>
> 如下所示, 有 5 种可以从 s 中得到 "bag" 的方案。
>
> babgbag
>
> babgbag
>
> babgbag
>
> babgbag
>
> babgbag

提示：

- 1 <= s.length, t.length <= 1000
- s 和 t 由英文字母组成

#### 115-CODE

定义一个二维的 DP 表 dp[i][j]，其中 i 对应 t 的前缀长度，j 对应 s 的前缀长度。

dp[i][j] 的含义：表示 t 的前 i 个字符（即 t[0:i]）在 s 的前 j 个字符（即 s[0:j]）中，作为子序列出现的个数。

对于 dp[i][j]，我们考虑 s 的第 j 个字符（即 s[j-1]）：

- 情况一：s[j-1] 不等于 t[i-1]：如果当前字符不匹配，那它对于构建 t 的前缀来说没有贡献。我们可以直接“跳过” s 的这个字符。
dp[i][j] = dp[i][j-1]
- 情况二：s[j-1] 等于 t[i-1]：如果当前字符匹配，我们就有两种选择：
	- “跳过”：不使用 s[j-1] 来匹配，结果继承自 dp[i][j-1]。
	- “使用”：用 s[j-1] 来匹配 t[i-1]，那么剩下的 t 的前 i-1 个字符就需要由 s 的前 j-1 个字符来构成，即 dp[i-1][j-1]。
	- 因此，总的方案数就是这两种选择之和：dp[i][j] = dp[i][j-1] + dp[i-1][j-1]

```go
func numDistinct(s string, t string) int {
	// 获取两个字符串的长度
	m, n := len(s), len(t)

	// 如果 t 的长度大于 s，那一定不可能构成，直接返回 0
	// 但 DP 表也能处理这种情况，不过为了效率，可以提前判断[reference:10]
	if n > m {
		return 0
	}

	// 1. 创建 DP 表，维度为 (n+1) x (m+1)
	// dp[i][j] 表示 t 的前 i 个字符在 s 的前 j 个字符中出现的次数[reference:11]
	dp := make([][]int, n+1)
	for i := range dp {
		dp[i] = make([]int, m+1)
	}

	// 2. 初始化：当 i == 0 时，即 t 为空字符串，方案数为 1[reference:12]
	for j := 0; j <= m; j++ {
		dp[0][j] = 1
	}

	// 3. 填充 DP 表
	for i := 1; i <= n; i++ {
		for j := 1; j <= m; j++ {
			if t[i-1] == s[j-1] {
				// 情况二：字符匹配，可以选择“使用”或“跳过”[reference:13]
				dp[i][j] = dp[i][j-1] + dp[i-1][j-1]
			} else {
				// 情况一：字符不匹配，只能“跳过”[reference:14]
				dp[i][j] = dp[i][j-1]
			}
		}
	}

	// 4. 最终结果：t 的全部 n 个字符在 s 的全部 m 个字符中出现的次数
	return dp[n][m]
}
```

- 两个根因
	- JSON解析缺陷：解析10MB商店目录JSON，sscanf反复调用strlen重复计算字符串长度，造成大量CPU损耗。

- 验证手段：编写DLL注入补丁，一是缓存strlen计算结果；二是直接跳过去重逻辑。两项修改完成后加载时间降至1分50秒，提速约69.4%。
- 后续结果：文章爆火，R星注意到此问题，破例给予10000美元赏金，随后官方推送补丁彻底修复加载性能问题。
- 技术启示：即使文件体积不大，低效的字符串处理、O(n^2)复杂度的暴力遍历，也会带来灾难性性能；闭源软件可以通过栈采样、内存转储做逆向性能分析。

### 5. [为什么大部分模型都有升维降维操作？（知乎）](https://www.zhihu.com/question/1956421703728076399)

> 来自 [元算](https://www.zhihu.com/people/1-67-9-10) 的 [回答](https://www.zhihu.com/question/1956421703728076399/answer/2032547562662662238)，发布时间：2026-04-28 19:51

我告诉你:

很多人第一次看到神经网络里的升维降维,都会产生一种很朴素但很正确的怀疑：

输入就那么点东西,你把它从 128 维变成 1024 维,难道信息就变多了吗？

当然不会。

如果你只是对同一个输入做一个确定性的变换,那么从信息论上讲,升维不可能凭空创造关于这个样本的新信息。你把一张照片展开成一百万维也好,把一句话映射到几千维向量也好,原始输入携带的信息上限就在那里。

所以,很多人会进一步推论：

那升维是不是只是为了塞更多参数？是不是模型工程师在堆料？

这个判断对了一半,但只对了很浅的一半。

升维确实经常会带来更多参数,更多参数确实会增强模型容量。但如果你只把升维理解成加宽网络、多塞参数,那你基本还停留在看模型结构图的阶段,没有真正理解神经网络到底在干什么。

神经网络里的升维降维,本质上不是为了增加信息。

它是为了改变信息的表达方式。

这句话非常关键。

你要把信息量和可计算性分开看。

一坨信息存在那里,不代表它容易被模型利用。现实世界里的数据,最恶心的地方就在于,有用的结构往往不是以人类或者线性模型喜欢的方式摆出来的。

举个最简单的例子。

你有两个输入变量 x 和 y,任务是判断它们是不是同号。

如果 x 和 y 同号,输出 1；异号,输出 0。

在原始二维平面里,这个分类边界不是一条直线能切开的。你拿一个普通线性分类器去做,它会很痛苦。因为这个任务真正需要的是乘积关系：xy 是否大于 0。

这时候你做一个看起来很傻的升维：

把原来的输入从：

x, y

变成：

x, y, xy

你发现事情突然变简单了。

在这个三维空间里,只要看第三个维度 xy 是正还是负,分类就结束了。

注意,这里没有产生新信息。xy 本来就由 x 和 y 决定。它不是凭空冒出来的,它只是把原来藏在变量交互里的结构,显式展开成了一个更容易被后续层读取的坐标。

这就是升维的第一层意义：

把隐含关系摊开。

你可以把它理解成数学里的换坐标系。

同样一个物体,在笛卡尔坐标系里可能描述起来很麻烦,换到极坐标系里一下子就清楚了。同样一个函数,在原始空间里可能非线性得一塌糊涂,映射到高维空间以后,可能变成一个简单的线性切分问题。

这就是传统机器学习里核方法的核心直觉。

支持向量机里的核技巧,本质上就是偷偷把数据映射到一个高维甚至无限维空间里,让原本纠缠在一起的数据变得更容易分开。它不是创造信息,它是在创造一个更好用的几何空间。

神经网络做的事情更暴力。

它不是手工规定一个升维规则,而是让模型自己学：到底该把哪些交互关系展开,哪些方向拉长,哪些方向压扁,哪些模式显式化。

所以，升维不是为了让信息变多。

升维是为了让信息变得好处理。

这就像你整理一个压缩包。

压缩包本身信息量很高,但是你没法直接阅读。你把它解压出来,占用空间变大了,文件数量变多了,但信息并没有凭空增加。它只是从高度压缩、难以操作的状态,变成了展开后、容易访问的状态。

神经网络里的很多升维,就是这个逻辑。

Transformer 里的 FFN 层就是最经典的例子。

一个标准 Transformer block 里,注意力层之后通常会接一个前馈网络。这个前馈网络经常会把维度从 d_model 升到 4 倍左右,比如从 768 升到 3072,然后再降回 768。

很多人看这个结构会疑惑：为什么非要先放大再缩回来？直接 768 到 768 不行吗？

理论上可以。

效果上通常不行。

因为中间那层高维空间,给模型提供了一个展开特征、做非线性组合、再压回主干空间的工作台。

你可以想象一个厨师做菜。

输入是一堆食材,输出是一盘菜。如果你让厨师只能在一个小碗里操作,他不是不能做,但很多步骤施展不开。你给他一个大案板,他把食材摊开、切碎、分组、调味、混合,最后再装回盘子里。

这个大案板不会凭空增加食材。

但没有这个大案板,复杂加工根本做不了。

Transformer 里的升维层,就是那个大案板。

模型先把每个 token 的表示投影到更高维空间。在这个空间里,不同的神经元可以分别响应不同的模式：语法结构、实体关系、情绪倾向、代码缩进、数学符号、因果连接、上下文角色等等。经过激活函数之后,模型再把这些被展开的模式压回原来的维度,交给下一层继续处理。

所以 FFN 里的升维,不是为了保存更多原始信息,而是为了制造更多中间计算通道。

这就是第二层意义：

升维提供计算空间。

你不能只把神经网络看成存储信息的容器。它更像一条加工流水线。中间层的维度越大,意味着同一时刻可以并行计算、筛选、组合的特征模式越多。

这就牵扯到参数问题了。

升维当然会增加参数。比如从 768 升到 3072,再降回来,这两个矩阵参数量非常大。很多大模型里,FFN 的参数量甚至占了整个 Transformer block 的大头。

但这些参数不是简单堆在那里好看。

参数的意义在于,它们存储了训练阶段从海量数据里学来的变换规则。

这也是很多人容易混淆的地方。

对于当前这个输入样本来说,升维没有增加新信息。

但是模型参数本身携带了从训练数据中学到的统计规律。

当输入 x 进入模型,输出的高维表示不是只由 x 的原始信息决定的,它还被参数 θ 加工过。这个加工过程相当于把当前样本和模型过去见过的世界经验进行匹配。

比如一个词 “bank”。

单看这个词,它可以是银行,也可以是河岸。输入 token 本身就那么一个 ID,看起来没什么信息。但模型参数里已经吸收了大量语料中 bank 的用法。当它看到上下文里出现 money、loan、interest,它会在高维表示里激活金融语义方向；看到 river、water、sand,它会激活地理语义方向。

不是输入自己变聪明了。

是模型参数把训练数据中的先验知识注入到了表示变换里。

所以更准确地说：

升维不增加当前输入的信息,但它让模型有空间把输入和参数中存储的知识发生复杂反应。

这才是神经网络真正可怕的地方。

接下来再说降维。

很多人对降维也有误解。他们觉得降维就是压缩,就是信息损失。既然信息会损失,为什么模型还要降维？

因为模型不需要保留所有信息。

模型需要的是任务相关信息。

你拍一张猫的照片,里面有太多无关细节：背景墙的纹理、光照噪声、相机传感器误差、桌子上的灰尘、压缩算法留下的伪影。对于判断是不是猫来说,这些东西大部分都是垃圾信息。

降维的核心作用,就是丢掉无关自由度,把模型真正需要的结构压出来。

这就像你看一个人,不需要记住他脸上每一个毛孔的位置。你只需要提取出轮廓、五官比例、关键特征,就能认出他是谁。

降维不是简单地把信息砍掉,而是把高维杂乱数据压缩成更抽象、更稳定、更有判别力的表示。

这就是为什么 CNN 里会不断下采样。

原始图像可能是 224×224×3,看起来维度很高。但里面大量像素级细节并不重要。模型通过卷积和池化,一层一层把局部边缘变成纹理,把纹理变成部件,把部件变成物体概念。空间分辨率降低了,但语义密度提高了。

表面上看,信息少了。

实际上,任务需要的东西更集中了。

这就像把一本书做摘要。摘要的字数比原文少,但如果摘要做得好,它对理解这本书讲什么这件事反而更有效。

再往深一点说,升维和降维一起构成了神经网络最基本的工作方式：

先展开,再筛选,再压缩。

先把原始输入映射到一个足够宽的空间里,让各种潜在模式有机会显现出来；然后通过非线性激活、注意力机制、归一化、门控等操作筛掉没用的部分；最后降维,把有用的信息重新压缩成下一层能继续处理的形式。

这不是多此一举。

这是复杂系统处理信息的基本范式。

你看大模型里的 MLP,很多地方都是：

低维表示 → 高维中间层 → 激活函数 → 低维表示。

你看 AutoEncoder：

输入 → 编码降维 → 瓶颈表示 → 解码升维。

你看 U-Net：

先下采样提取全局语义,再上采样恢复空间细节,中间还要用跳跃连接保留局部信息。

你看推荐系统：

用户和商品的巨大稀疏特征先嵌入到 dense embedding,再经过多层交互网络,有时升维做特征交叉,有时降维做最终排序。

不同模型结构长得不一样,但底层逻辑高度一致：

原始空间不是最适合计算的空间。

模型要不断把数据搬到更合适的空间里。

有时候要升维,因为关系太隐蔽,要展开。

有时候要降维,因为噪声太多,要压缩。

有时候先升后降,因为要在中间完成复杂加工。

有时候先降后升,因为要提取核心语义再重建细节。

这就是表示学习。

神经网络最重要的能力,不是直接从输入到输出做一个暴力拟合,而是学会中间应该怎么表示这个世界。

回到你的问题：

升维会不会得到更多信息？

不会。

如果从严格信息论角度看,一个确定性升维函数不可能增加原始输入的信息量。

但这句话本身对理解神经网络帮助不大。

因为模型真正关心的不是信息总量,而是信息是否处在适合当前任务的坐标系里。

一张皱巴巴的地图,信息都在,但你很难用。把它摊平、标注、分层、重新投影,并没有增加地理事实,但会让导航变得可行。

升维就是摊平和展开。

降维就是抽象和压缩。

参数就是模型从历史数据里学来的投影规则。

非线性就是让每一次投影不只是换个坐标,而是能够真正改变几何结构。

所以,不要再把升维降维理解成维度数字的变化。

维度只是表象。

真正发生的是：

模型在不断寻找一个更适合解决问题的空间。

在这个空间里,原来纠缠在一起的模式会分开,原来不可见的交互会显现,原来杂乱的噪声会被压掉,原来复杂的任务会变成一个更简单的几何问题。

这才是升维降维的本质。

不是信息变多了。

是这个世界被重新摆放了一遍。

### 6. [有哪些算法惊艳到了你（知乎）](https://www.zhihu.com/question/26934313)

> 来自 [BugBuster喵](https://www.zhihu.com/people/4u93e) 的 [回答](https://www.zhihu.com/question/26934313/answer/2000296018831511840)，发布时间：2026-01-29 19:55

这是我面试高级工程师时很聊的话题之一。

听大家说了很多，我也来聊几个真正让我感到惊艳，甚至改变了我对计算机科学认知的算法。

#### 1. 扔硬币的艺术：HyperLogLog

很多年前，我还在做广告系统的时候，遇到了一个非常经典的需求：统计UV。

如果网站只有几千人访问，这太简单了。你弄个哈希表，来一个IP丢进去一个，最后看集合的大小就行。

但是，当你的用户量是亿级别的呢？

假设你有1亿个用户，每个用户ID是长整型占8字节。光是存这1亿个ID，就需要几百兆内存。如果你还要统计每天、每小时、不同维度的UV，内存瞬间就会爆炸。

当时我还在死磕怎么压缩数据，后来一位前辈丢给我一篇论文，就是关于HyperLogLog的。

看完我整个人都傻了。这个算法告诉我，统计1亿个基数，只需要12KB的内存，误差还能控制在1%以内。

它是怎么做到的？它的核心思想居然是扔硬币。

想象一下，你和朋友玩扔硬币游戏。如果你说你连续扔出了3次正面，我不觉得稀奇。但如果你说你连续扔出了20次正面，我会断定你肯定扔了成千上万次硬币，或者你就是在作弊。

伯努利试验告诉我们，抛硬币出现连续正面次数越多，说明你需要尝试的实验总次数就越多。

HyperLogLog就是利用了这个概率学原理。它把每个用户ID哈希成一串二进制，这串二进制里的0和1，就相当于硬币的反面和正面。通过观察哈希值中末尾连续零的最大数量，就可以倒推估计出你到底放进了多少个不同的数据。

惊艳点在哪里？

它完全抛弃了存储数据本身的执念。传统的思维是：我要数人头，我就得把每个人头都记下来。HyperLogLog的思维是：我不记人头，我记人头出现的特征概率。

这种从确定性记录到概率统计的思维跨越，是我职业生涯中第一次感受到数学的暴力美学。它不追求100%的精准，但在海量数据面前，99%的精准度加上极致的资源节省，就是完美的工程解。

如果你对这种概率算法感兴趣，想深入看看它的推导过程（哪怕看不懂公式，看图也好），我强烈推荐你去读一下Redis作者Antirez的博客。他在实现Redis的PFCOUNT命令时写过非常详细的解释。你搜 *Redis HyperLogLog explanation* 就能找到，那绝对是把复杂理论工程化的典范。

#### 2. 宁可错杀，不可放过：Bloom Filter

接上面的话题。有了UV统计，自然就有去重需求。

比如爬虫系统，我有100亿个URL，来了一个新URL，我怎么知道它是不是已经爬过了？ 或者在垃圾邮件过滤里，怎么判断这个发件人是不是黑名单？

还是老问题，存不下。

这时候布隆过滤器登场了。它的设计哲学简直就是无赖。

它搞了一个很长的二进制位数组，初始全是0。来一个数据，用好几个不同的哈希函数算出好几个位置，把这几个位置都标记为1。

查询的时候，同样算这几个位置。如果这些位置全都是1，它就告诉你：这东西可能存在。如果有一个位置是0，它就告诉你：这东西绝对不存在。

注意那个可能。

布隆过滤器的惊艳之处在于它承认自己会犯错。它会有误判，可能会把没见过的东西误判为见过的。但是，它绝不会漏判。

在工程实践中，这种有底线的妥协简直是天才的设计。

举个真实的场景：缓存穿透保护。 我们在做高并发系统时，最怕有人疯狂查询一个数据库里根本不存在的key。请求会直接穿透Redis缓存打到MySQL数据库上，瞬间把数据库打挂。 怎么防？我们在Redis前面挡一层布隆过滤器。

所有存在的key都放进布隆过滤器。请求来了，先问布隆过滤器：这key在吗？ 布隆过滤器说：不在。那好，直接拦截，不用查数据库了。 布隆过滤器说：在。那放过去查，虽然有极小概率其实是不在的（误判），但这点漏网之鱼对数据库已经构不成威胁了。

这给了我极大的震撼：完美的算法不一定是没有任何错误的算法，而是能把错误控制在可接受范围内，并换取巨大性能收益的算法。

关于这个，我建议大家不仅要看原理，更要去玩一下可视化演示。Jasper Wang有一个非常棒的Bloom Filter Visualization在线演示网页，你搜一下就能出来。你能亲眼看到哈希冲突是怎么发生的，那种直观的感受比看十页书都管用。

#### 3. 来自高维空间的降维打击：Word2Vec

时间来到2013年左右，那时候深度学习还没像现在这么火。做NLP的人还在搞词袋模型、TF-IDF这些统计方法。

然后Word2Vec横空出世。

当你第一次看到那个著名的公式：King - Man + Woman = Queen 时，你的反应是什么？

我的反应是：你在扯淡吧？词语怎么能做加减法？

但当你真正理解了Embedding这个概念时，你会发现这简直是上帝视角。

计算机是不懂中文、英文的，它只懂数字。以前我们给词编码，要么是编号（1是苹果，2是香蕉），要么是One-hot（一长串0，只有一个位置是1）。这些表示方法里，词与词之间是孤立的，没有任何关系。

Word2Vec把每个词映射到了一个高维向量空间里。

在这个空间里，意思相近的词，距离就很近。意思相反的词，距离就很远。词与词之间的关系，变成了向量空间里的方向和距离。

- 为什么 King - Man + Woman = Queen？
- 因为在向量空间里，从King到Man的距离向量，代表了性别剥离。
- 把这个向量应用到Woman身上，就加上了皇室属性，结果自然就指向了Queen。

这不仅仅是算法的胜利，这是哲学的胜利。它告诉我们，语言的意义不是定义出来的，而是由上下文决定的。

这个算法直接开启了后来的万物皆Embedding时代。现在的推荐系统（比如你刷知乎、刷抖音），底层全是这个逻辑。把你这个人变成一个向量，把视频变成一个向量，算一下余弦相似度，高的就推给你。

想真正理解这个，我强烈推荐Jay Alammar的博客。这位大神是把AI原理可视化的神级人物，他的文章 _The Illustrated Word2Vec_ 是我见过最清晰的讲解，没有之一。我也经常把他的博客发给刚入职看不懂Transformer的小朋友们。

#### 4. 雷神之锤的平方根倒数

这个例子可能有点老，但每次提起来我都得跪着写。

在3D游戏开发中，经常需要计算平方根倒数（1/sqrt(x)），主要用于向量归一化。在早期的硬件条件下，浮点除法和开方运算昂贵得要命。

然后，在《雷神之锤III》的源码里，大家发现了这么一段C语言代码：

```c
float Q_rsqrt( float number ) {
	long i;
	float x2, y;
	const float threehalfs = 1.5F;

	x2 = number * 0.5F;
	y  = number;
	i  = * ( long * ) &y;                       // evil floating point bit level hacking
	i  = 0x5f3759df - ( i >> 1 );               // what the fuck?
	y  = * ( float * ) &i;
	y  = y * ( threehalfs - ( x2 * y * y ) );   // 1st iteration
	return y;
}
```

注意那行注释：what the fuck?

这行代码的核心在于那个魔术数字：0x5f3759df。

写这段代码的人（有人说是卡马克，但考证后可能是其他大牛）利用了IEEE 754浮点数的二进制表示结构，通过一次整型位移和减法，直接猜出了一个非常接近的近似值，然后用牛顿迭代法稍微修了一下。

它的速度比系统的sqrt函数快了4倍。

当我第一次搞懂它的原理时，我意识到：真正的黑客，是在比特级别思考问题的。 他们看到的不是数字，而是内存里那一排排开关。

这种算法虽然现在随着硬件指令集升级已经不再需要了，但它代表的那种打破常规、利用底层特性榨干硬件性能的精神，是现在很多只会调包的程序员最缺少的。

#### 5. 一致性哈希：分布式系统的定海神针

如果你做过后端，肯定知道负载均衡。

把请求分发给后端服务器，最简单的方法是 hash(key) % N，N是服务器数量。

这听起来很完美。直到有一天，你的一台服务器挂了，N变成了N-1。 或者你的业务爆发了，你需要加机器，N变成了N+1。

这时候灾难发生了：几乎所有的请求都会被重新映射。所有的缓存瞬间失效，流量像海啸一样打到数据库，你的系统瞬间雪崩。

一致性哈希用一个非常优雅的圆环结构解决了这个问题。

它把数据和服务器都映射到一个0到2^32的圆环上。数据顺时针找最近的服务器节点。

- 当一台服务器挂了，受影响的只有它是逆时针方向的那一小部分数据，其他数据不动。
- 当你加一台服务器，它只分担它逆时针方向那一部分压力，其他服务器不受影响。

我第一次接触这个算法是在看Memcached的客户端源码时。当时我就感叹，这简直是拓扑学在计算机工程里的完美应用。它把离散的哈希点连成了连续的环，用几何的思路解决了算术的问题。

现在所有的分布式存储、分布式数据库、包括像Dynamo、Cassandra这些顶级的系统，底层都在用这个思想。

如果你想深入了解分布式系统，我推荐去读一下Amazon Dynamo的经典论文 _Dynamo: Amazon’s Highly Available Key-value Store_。虽然是十几年前的论文，但它是一致性哈希在工业界大规模应用的鼻祖，读完你会对所谓的高可用有全新的认识。

#### 6. 反向传播：让机器学会下山

最后，必须得说说现在AI的基石：反向传播。

虽然现在大家天天炼丹，PyTorch一个 `.backward()` 就完事了，但当你深入理解它背后的链式法则和梯度下降时，你还是会被感动。

想象一下，你被蒙住双眼放在一座高山上，你的目标是下到山谷底。你不知道方向，但你能感觉到脚下的坡度。 如果你往某个方向迈一步，感觉是上坡，那你就退回来；如果是下坡，你就大步走。

神经网络训练就是这个过程。

- 前向传播是机器在瞎猜。
- 损失函数告诉机器猜得有多离谱。
- 反向传播就是把这个“离谱程度”一层一层往回传，告诉每一个神经元：是你小子把结果搞坏了，你得调整一下你的参数（权重）。

这个算法的惊艳之处在于，它把学习这个极其抽象的概念，具象化成了求导数。人类的智能是基于经验的，而机器的智能是基于微积分的。

它简单到只需要高中数学就能推导，但强大到能支撑起现在的ChatGPT。

对于想入门AI的朋友，不要一上来就去啃西瓜书里的公式。我强烈推荐3Blue1Brown的深度学习系列视频。他在B站和YouTube都有号。他用动态的几何图形展示了梯度是如何在网络中流动的，看完你会有一种原来如此的通透感。

写了这么多，其实你会发现，这些惊艳的算法都有一个共同点：

它们往往不是在硬算，而是在“偷懒”。

- HyperLogLog偷懒不存全量数据，改玩概率。
- Bloom Filter偷懒不追求100%准确，改换速度。
- Word2Vec偷懒不搞复杂语法规则，改算距离。
- 一致性哈希偷懒不搞全局重排，改搞局部调整。

作为一名在IT行业摸爬滚打多年的老兵，我最大的感触是：算法的本质，是对问题维度的重构。

刚入行时，我觉得算法就是写出更复杂的逻辑来覆盖所有情况。 后来我才明白，高阶的算法是跳出当前的逻辑维度，用概率、用几何、用物理的思维去降维打击。

现在的年轻人很焦虑，觉得算法岗卷，觉得模型都封装好了没啥可学的。

其实不然。工具变了，API变了，但解决问题的思维模式是不变的。

当你面对一个棘手的业务场景——比如如何在有限的内存里去重，如何在分布式的环境下保持一致，如何在海量数据里挖掘关系——你能脑子里蹦出这些经典的算法思想，并且知道怎么因地制宜地魔改它们，那才是你不可替代的核心竞争力。

这也是为什么我总是建议新人：多看论文，多读源码，少背面试题。面试题能让你进大厂，但对数据和算法的深刻洞察，才能让你在这个行业里走得远，走得稳。保持好奇心，这个世界可以用代码算出来，这事儿本身就挺惊艳的，不是吗？

### 7. [现在社会普通人的出路在哪里？（知乎）](https://www.zhihu.com/question/616978474)

> 来自 [烟雨江湖见闻录](https://www.zhihu.com/people/8-68-27-24-22) 的回答，原答案已经不可见了，作者也被封号了，此文是在 X 上看到的

两个建议。

我认为首先，这届年轻人要做的第一件事，就是不要去相信上一代享受了时代红利和收益的人给出的各种人生经验，比如说努力奋斗，好好上班可以致富，未来有无限可能等等。

因为你们面临的大环境是截然不同的。

这届年轻人要充分想明白，你们面临的大环境下，劳动力就是贬值的。表现在和过去的年轻人相比，同等条件下却找不到同等条件的工作，只能接受待遇更低的工作，或者是工作环境、时间精力要求更高的工作。

大部分年轻人如今找到的工作，他们所承担的环节，大都是纯消耗型的内容，消耗了年轻人的时间和精力，却没有任何自我技能方面或者职场竞争力上的提升。所以，即使五到十年后，会有新一波经济繁荣期到来，这批年轻人大多数已经三十岁甚至往上，不再年轻，但他们的职场竞争力可能同新的应届毕业生没有太大差别。

甚至如果有新型产业崛起，新的工作机会也不会落到这批在这个新兴领域毫无积累的年轻人头上。

除此之外，还有两个建议，是这届年轻人可以仔细考虑并付诸实践的：

第一个建议是认清现实，积极苟住。

认清现实说的是不要幻想自己会平稳的上升，不断升职加薪，走上人生巅峰，打工就是打工，不需要有那种"公司是我家"的责任感和荣誉感，你和资本家就是单纯的买卖关系，不要相信"好日子还在后头呢"的画大饼，认真工作，但不要过度工作，锻炼身体，保持一个健康的身心。

积极苟住，说的是在现行的环境下，如果两年还没考上公或者研，家境一般的就不要再继续挣扎了，赶紧先找一份工作，不要过度消费，做好理财规划，手握存款，存款就是你抵御风险的本钱。

第二个建议，如果不甘心一辈子就这样了，就要在稳住的同时还要浪一把。

这个浪，其实是在看不清下一个时代方向时的一种“低成本试错”。

我刚刚已经说了，这代年轻人，靠上班大概率只能温饱。

要想把握住下一个时代的方向，只能是在有稳定的大盘下，进行积极的试错。

我推荐几个思路，可以结合起来完成。

第一个是多读书，读历史读政治读经济读金融，不要看碎片化的公众号文章，去啃大部头，去培养系统性的思维，培养自己那种能在迷雾中看透真相的能力。

要能清晰的认知这个世界韭菜是如何被收割的，以及如何做能够避免被收割。读完后还要实践和思考，这个的目的是为了让你对时代的脉搏和机会有更加敏锐的感知。

第二个是在一的基础上，你结合自己判断的未来有可能有机会的方向，或者是你认知自己有天赋和才能的方向，去做一些副业。

注意我说的是副业而不是兼职，副业是事业，事业是随着你时间精力的投入，能够为你带来复利效应的。

因此，最好的副业就是你能自己掌握生产资料。

我随便举几个例子：

比如说如果你笔头比较好，你就好好写文章，认真经营自己的公众号啊知乎什么的，这个就叫副业。但如果你是给其他公众号投稿，或者是给工作室当枪手，这就不叫副业，这叫兼职，因为这个事情除了赚些外快，并没有给你积累粉丝等重要的资源。

可以多做几个副业，多方向试错。

但我不建议尝试成本太高的副业，大环境不好的情况下副业也会很卷，成功率也很低，大多数普通人都没有承受高成本创业失败的资本。

最好是从一些投入低的副业入手，就算做不成功，也能掌握一门技能，以后失业了也还能凭借技能混口饭吃。

这个就是底线思维。

以上两个建议，只针对相对来说人际交往能力一般，但学习和思维能力比较强的朋友们。毕竟，这个世界上不同类型的人，有不同方式的生存之道。

普适性地说说，我觉得首先是要踏实下来，摒弃掉一切媒体和文学作品带给你的价值观，从生活出发，好好审视下自己，然后再去思考生活的真相，寻找适合自己的发展道路，真的，这是最重要的一点。

所有你能接触到的信息，都是在以某种隐藏版的方式给你讲故事。

这些故事有意无意地隐藏了那些真实事件中的关键点，只讲述最有利于传播的奇闻异事，对这些故事和道理无条件的全盘接受，带来的有错误的认知。

那什么叫做从生活出发呢？

我们换一个视角看自己。

假设这是一档历史求生节目，你是一个历史人物，生活在二十一世纪这个历史时期，往后看五十年，什么对你来说是最重要的呢？

我想所有回答你具体细节的人都是骗子，无论他们谈论的是什么终生学习还是人工智能。

真正的道理很简单，任何时代，没有人能预知未来，我们只能活在当下。

站在当下，我们只能尽量保证自己是处在正向循环中，明天要比今天好。

一个人掉在大海里，需要做的第一件事，是让自己能够呼吸。不管用什么姿势，能浮在海面上，保持正常的呼吸，这一定是当下最重要的事。这时候看什么孙杨的游泳视频，没用，远水解不了近渴。

所以我说，先要认清自己，了解自己的各项情况，包括所处的环境。（仅仅在个人事项的紧急与重要程度方面，你可以画一个直角坐标系，从第一象限到第四象限依次为“紧急又重要”、“紧急不重要”、“重要不紧急”、“不重要不紧急”。）

你意识不到你在海里，你还去学别人跑步，你马上就被淹死。

认清了所处的环境，下一步干嘛呢？

套路是固定的，你需要了解你生存下去的必要条件，并且列出优先级。

我很喜欢看一个野外生存节目叫《单挑荒野》，探险者艾德孤身深入荒野，不带任何现代求生工具，只能靠自己活下来。（自身可运用SWOT模型，或者其他的思维模型。）

他每集一开始都会念叨一句话：“接下来我需要解决最重要的东西——水源、居住地、食物和火。”

为什么要念叨，是因为这需要变成一种习惯，即使你意识模糊的时候也能想到，让你有自救的能力。

那么，对于在现代文明中生活的我们而言，什么是生存要素呢？

我的观点——金钱、业余时间、技能和冒险精神。

这四点对比起野外生存而言显得更抽象一些，但这正是文明发展的象征。

我逐一解释下。

金钱：支撑生存和发展的必要资源，必须有经济来源。

业余时间：必须有一定的个人空间和时间来进行思考和规划，用来感知和应付变化，形成正向循环。

技能：用来进行交换和出卖的实用技能，保持精进和拓展，让自己的经济状况更好。（普通人没什么资产，现金流就是自己的生命线。）

冒险精神：用来突破舒适区，探索未知领域，扩大认知、更新自己的思维体系。

为什么这四项是生存要素？因为他们可以帮助你正向滚动下去，形成正反馈。你可以好好检视下自己这几项有否缺失，然后针对性的去完善。

例如说，你特别缺钱，那你应该先什么都不想，给自己挣到能踏实生活半年的物质基础。或者，你缺过硬的技能，那就选择自己擅长的领域，认真开始修炼一门。

同样，工作时间太满，自己完全腾不出时间跟精力来思考自己未来发展方向的工作，工资高也不要选，因为你迟早被透支，还会失去应付变化的能力。

当然，如果工资特别高除外，短期迅速积累经济也很重要。

这些在你进入一个新环境之前就最好想清楚。

认识清楚环境也同样非常重要，因为这可以防止你定出不切实际的目标。

艾德在节目里经常反省自己的决策，反省的最多的就是自己的盲目扩张和过高目标。比如老想着去抓一头大动物而忘记找点小食物，想搭一个大屋子结果发现材料不够。或者过渡关注一种资源而忽视其他。

例如特别着急生火而忘记去寻找食物以及做陷阱等等。订错目标换来的就是饿肚子、受冷以及其他更危险的后果。

现代生存也是如此，好高骛远，被蛊惑被鸡血都不是好事，你要意识到生存是件不容易的事，这并不是轻轻松松万事俱备的游戏世界。

你必须尊重这个世界，尊重的意思即是，了解它的客观性，知道它并不特别针对谁，它有自己的运行逻辑，而如果你随随便便应付生活，生活也会应付你，所以只能认真地去面对每一个出现的问题。

艾德每次的生存结果都随着环境的变化而不同，有的地方饿得快挂掉，有的地方却还能给自己做一顿烛光晚餐。

跟环境有关，有时候跟运气也有关。所以其实也得意识得到人力是有限的，并不是按着某个道理去做就一定能有如何的结果。

尽人事听天命，我想这也是健康生存的必要认知。

### 1. 棘轮效应

棘轮效应，用大白话讲就是四个字：由奢入俭难。更学术一点的说法是： **消费习惯具有不可逆性，往上调整容易，往下调整极难。**

经济学里，它特指杜森贝利（James Duesenberry）提出的“相对收入假说”： **你的消费水平，不仅取决于你现在赚多少钱，更取决于你过去曾经达到过的最高收入。那个巅峰时刻，就像一只“棘轮”（一种只能单向转动的齿轮）——把你卡在了那个高消费的档位上，降不下来。**

#### 核心机制：为什么“上去就下不来”？

触发棘轮效应的“扳机”有两个：

1. 习惯形成（生理惰性）：你用惯了洗碗机、开惯了带座椅加热的车、住惯了有落地窗的房子。这些体验会重塑你的“舒适区底线”。一旦习惯了某种便利和舒适，再回到粗糙的状态，身体和大脑会持续发出“不适”信号。
2. 攀比效应（心理锚定）：你的“参照系”不是“自己以前多穷”，而是“朋友圈里现在都啥样”。一旦你的收入让你够到了某个圈层的入门消费（比如喝精品咖啡、办高端健身卡），你就很难在朋友圈里“降级”，因为那感觉像承认自己“不行了”。

#### 生活中的“棘轮”时刻

**1. 薪资与跳槽（最大的陷阱）**
你在一家高薪但极度内耗的公司拿了3年高薪，每天痛苦不堪。终于想跳槽，但新公司给不了同等薪资，只能给到降薪15%。
你大概率会拒绝，心想：“我凭什么越混越回去？”
但你没算的是：**原公司的“高薪”是买你“痛苦”的溢价**。你被棘轮效应卡住了那个工资数字，却没算上精神损耗、健康成本。这就是为什么很多人宁可在一份厌恶的工作里“高位站岗”，也不敢降薪换个舒坦。

**2. 租房与住房（最刚性）**
刚毕业住1500的合租单间，月薪2万后换了8000的单身公寓。后来失业或换城市，收入腰斩，你发现自己**宁可借钱也不愿搬回1500的房子**。因为你的大脑已经把那8000块的“独卫、阳台、落地窗”定义为“正常生活”，搬回去就等于“人生倒退”。

**3. 日常消费品（温水煮青蛙）**
从超市速溶咖啡换成便利店现磨，再换成自己买咖啡机做手冲。一旦你习惯了手冲，出门在外让你喝速溶，你会觉得像在喝药。你的“咖啡底线”被永久抬高了。

#### 它与“损失厌恶”的关系

你可以这么理解这俩“兄弟”：

- **损失厌恶**：告诉你“失去100块比得到100块更痛”。
- **棘轮效应**：告诉你“降低生活水平，就是一种巨大的‘失去’”。

棘轮效应之所以可怕，是因为它在**把你的“生活水平”变成一个锚点**。降薪或降消费时，触发的是**全方位的损失厌恶**——你失去的不只是钱，而是“住好房”“吃好饭”“被人羡慕”的感觉。所以你的**反抗强度**远大于“理性权衡现状”。

#### 棘轮效应的最大风险：“金手铐”

最危险的是“负债型棘轮”：
当你涨薪后，立刻背上更高的房贷、车贷，办了更贵的健身卡。这时你的每月固定支出被“棘轮”卡在了高位。从此，你的职业选择不再基于“喜不喜欢”或“长不长远”，而只基于“下个月房贷在哪”。你被自己的高消费给“锁死”了。

#### 如何“反杀”棘轮效应？（3条行动指南）

- 方法1：涨薪后的“30天冷静期
	- 每次加薪或拿到意外之财，千万不要立刻升级你的“固定开支”（比如换租更贵的房、立刻换车）。
	- 先把增量部分的50%强制储蓄或定投。只允许用剩下的50%，且只能用于“一次性体验”（比如一次旅行、一个奢侈品包），绝不能变成“每月固定开销”（比如租更贵的房）。
	- 因为一次性消费不会形成“棘轮”，而固定开销会。
- 方法2：区分“提升资产”和“提升消费
	- 把“住得好”改成“住得精”——用软装（绿植、灯光）提升品质，而不是直接换大房子。
	- 把“吃得好”改成“吃得更健康”——买好的食材自己做，而不是天天人均300的餐厅。
	- 升级“资产”（你的身体、技能、居住舒适度本身），而不是升级“负债型消费”（月供、会员费）。
- 方法3：定期做“降级模拟测试”（重置参照系）
	- 每半年抽一个周末，强迫自己过一天“刚毕业时的生活”：骑共享单车、吃路边摊、不点外卖自己做简单的面。
	- 这个动作不是为了省钱，而是为了把你的心理“参照系”往下拉一拉。让你大脑记住：“低配生活我其实也能过，并不痛苦。”

这样当你真正面临职业转型或经济下行时，你不会因为恐惧降级而做出错误决策。

#### 最后一句“清醒剂”

棘轮效应告诉我们：**你上一次的“成功”（高收入）往往是你下一次“自由”（敢辞职、敢选择）的敌人。**

真正的财务自由，不是你能挣多少钱，而是**你的消费水平“卡”在哪个档位**。如果你的“棘轮”卡在月薪3万的档位，你需要300万本金才能自由；如果卡在月薪1万的档位，你只需要100万。**你每升一级消费，都是在把自己的“自由门槛”往上抬一截。**
