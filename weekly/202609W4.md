### 1. ZIP、7z、XZ 介绍

可以把 **ZIP、7z、XZ** 先理解成三种不同层次的东西：

* **ZIP**：一种“压缩包格式”，里面可以放多个文件，每个文件通常独立压缩。
* **7z**：一种“压缩包格式”，设计目标是高压缩率，常用 **LZMA/LZMA2**。
* **XZ**：一种“单文件压缩格式”，核心也是 **LZMA2**，通常用于压缩 `.tar` 之类的文件。

真正决定“怎么压缩”的，主要是里面使用的**压缩算法**。

#### 1. 先理解压缩的核心：重复数据

例如：

```text
abcabcabcabcabcabc
```

直接存储需要很多字节。

压缩算法会发现：

```text
abc
```

重复出现了很多次，于是可以表示成类似：

```text
abc × 6
```

实际算法当然比这个复杂很多。

主流无损压缩基本可以拆成两类思想：

##### 第一类：找重复

例如：

```text
ABCDEFGABCDEFGABCDEFG
```

发现后面的内容和前面已经出现过。

于是可以记录：

```text
复制前面距离 7 个字节的位置，长度 14
```

这就是 **LZ 系列算法**的核心思想。

##### 第二类：让高频数据用更短的编码

假设数据中：

```text
A 出现 70%
B 出现 20%
C 出现 10%
```

那么没必要给 A/B/C 都分配同样长度的编码。

可以：

```text
A -> 0
B -> 10
C -> 11
```

这类思想就是 **Huffman / Range Coding / Arithmetic Coding** 等熵编码。

所以现代压缩算法经常是：

```text
找重复
   ↓
转换成更容易压缩的形式
   ↓
熵编码
   ↓
压缩数据
```

#### 2. ZIP

ZIP 本质上是一个**容器格式**。

最常见的压缩算法是：

> **DEFLATE = LZ77 + Huffman**

可以粗略理解成：

```text
原始数据
   ↓
LZ77 找重复
   ↓
(length, distance)
   ↓
Huffman 编码
   ↓
压缩数据
```

例如：

```text
hello hello hello hello
```

LZ77 会尝试把重复部分表示成：

```text
hello
<重复之前的数据>
<重复之前的数据>
<重复之前的数据>
```

然后 Huffman 再进一步压缩这些符号。

##### ZIP 的一个重要特点

ZIP 通常是：

```text
ZIP
├── a.txt → DEFLATE
├── b.txt → DEFLATE
├── c.jpg → DEFLATE
└── d.exe → DEFLATE
```

每个文件可以独立压缩。

所以：

```bash
zip archive.zip a.txt b.txt c.txt
```

本质上是在 ZIP 容器里保存多个压缩成员。

##### 优点

* 历史悠久
* 支持非常广
* Windows/macOS/Linux 基本都支持
* 可以随机提取其中某个文件

##### 缺点

DEFLATE 的压缩率已经不算特别高。

#### 3. 7z

7z 是一种**压缩容器格式**。

它最常见的核心算法：

> **LZMA / LZMA2**

可以简单理解成：

```text
7z
 ↓
LZMA/LZMA2
 ↓
字典匹配 + Range Coding
```

LZMA 的核心仍然是：

> **大量寻找之前出现过的重复数据。**

但它的字典通常可以非常大。

例如：

```text
AAAAAAAA........
```

或者：

```text
某个大型项目中反复出现的代码/文本
```

如果这些重复内容距离很远：

```text
A ................. A
```

LZMA 可以利用较大的字典找到它们之间的关系。

##### LZMA 为什么压缩率通常比 DEFLATE 高？

可以简单理解成：

```text
DEFLATE
字典相对较小
+
LZ77
+
Huffman
```

而：

```text
LZMA
更大的字典
+
更复杂的匹配模型
+
Range Coding
```

因此 LZMA 可以更努力地寻找重复。

代价就是：

```text
压缩：
CPU ↑
内存 ↑
时间 ↑

解压：
通常也比 ZIP 稍重
```

所以 7z 经常适合：

> **我不太在乎压缩时间，希望文件尽可能小。**

#### 4. XZ

XZ 和 7z 有一个非常有意思的关系。

XZ 通常使用：

> **LZMA2**

所以可以粗略理解：

```text
7z ──→ 常用 LZMA/LZMA2
          ↑
          │
XZ ───────┘
```

但它们不是同一个文件格式。

例如：

```text
xxx.7z
```

是一个**归档/压缩容器**。

而：

```text
xxx.xz
```

更像是：

> **把一个数据流压缩起来。**

所以 Linux 中经常看到：

```text
xxx.tar.xz
```

其实是：

```text
很多文件
   ↓
tar
   ↓
xxx.tar
   ↓
xz / LZMA2
   ↓
xxx.tar.xz
```

也就是说：

**tar 负责“打包”，xz 负责“压缩”。**

#### 5. 为什么 Linux 特别喜欢 `.tar.xz`？

因为 UNIX/Linux 很喜欢把：

> **打包和压缩分开处理。**

例如：

```bash
tar -cf source.tar source/
```

先打包：

```text
source/
├── a.c
├── b.c
├── c.h
└── README
       ↓
source.tar
```

然后：

```bash
xz source.tar
```

得到：

```text
source.tar.xz
```

所以：

```text
tar = 打包
xz  = 压缩
```

而 ZIP/7z 通常把：

```text
打包 + 压缩
```

放在一个格式里面。

#### 6. 三者放一起比较

|      | ZIP            | 7z                  | XZ           |
| ---- | -------------- | ------------------- | ------------ |
| 本质   | 压缩包格式          | 压缩包格式               | 压缩格式         |
| 常见算法 | DEFLATE        | LZMA/LZMA2          | LZMA2        |
| 核心思想 | LZ77 + Huffman | LZMA + Range Coding | LZMA2        |
| 压缩率  | 中等             | 较高                  | 较高           |
| 压缩速度 | 较快             | 较慢                  | 较慢           |
| 解压速度 | 较快             | 中等                  | 中等           |
| 内存需求 | 较低             | 较高                  | 较高           |
| 多文件  | 原生支持           | 原生支持                | 通常需要 tar     |
| 常见场景 | 通用文件交换         | 高压缩率归档              | Linux 软件包/源码 |

#### 7. 一个很重要的区别：压缩 ≠ 打包

这是理解 ZIP / 7z / XZ 最关键的一点。

例如有：

```text
a.txt
b.txt
c.txt
```

##### ZIP

```text
           ZIP
       ┌────┼────┐
       ↓    ↓    ↓
     a.txt b.txt c.txt
       ↓    ↓    ↓
     压缩  压缩  压缩
```

ZIP 同时承担：

```text
打包 + 压缩
```

##### 7z

类似：

```text
             7z
       ┌──────┼──────┐
       ↓      ↓      ↓
      a.txt  b.txt  c.txt
         ↓    ↓    ↓
          LZMA/LZMA2
```

也是：

```text
打包 + 压缩
```

##### tar.xz

则是：

```text
a.txt ─┐
b.txt ─┼→ tar → tar.xz → xz
c.txt ─┘
```

这里：

```text
tar = 打包
xz  = 压缩
```

#### 8. 最后用一句话记忆

你可以直接这样记：

```text
ZIP = DEFLATE = LZ77 + Huffman
```

```text
7z = 容器 + LZMA/LZMA2
```

```text
XZ = LZMA2 压缩流
```

而底层核心思想其实都可以归结到：

```text
寻找重复
   ↓
用“引用”代替重复数据
   ↓
统计概率
   ↓
高频内容用更短编码
   ↓
得到压缩数据
```

### 2. 什么是“熵”？

可以把**熵（Entropy）**先忘掉公式，用一句人话理解：

> **熵 = “一个随机变量有多不确定”或者“平均每次需要多少信息来描述它”。**

这两个说法其实是同一件事的两面。

#### 1. 先从“猜东西”理解熵

假设我让你猜一个硬币结果：

```text
正面：50%
反面：50%
```

你不知道下一次是什么。

所以不确定性比较高。

如果我换成一个特殊硬币：

```text
正面：99%
反面：1%
```

你基本可以直接猜：

```text
正面
```

所以不确定性很低。

因此：

```text
50% / 50%
    ↓
熵高

99% / 1%
    ↓
熵低
```

#### 2. 极端情况就更明显了

如果：

```text
正面：100%
反面：0%
```

那么你根本不用猜。

每次一定是正面。

所以：

$$
H=0
$$

**熵为 0。**

这很好理解：

> 没有任何不确定性，就不需要额外的信息。

#### 3. 熵的公式

对于离散随机变量：

$$
H(X)=-\sum_i p_i\log_2p_i
$$

例如硬币：

```text
正面：50%
反面：50%
```

那么：

$$
H=-0.5\log_2(0.5)-0.5\log_2(0.5)
$$

因为：

$$
-\log_2(0.5)=1
$$

所以：

$$
H=1\text{ bit}
$$

意思是：

> 平均来说，描述一次硬币结果需要 1 bit。

这和计算机的二进制正好对应。

#### 4. 为什么叫“平均信息量”？

前面我们讲过：

$$
I(x)=-\log_2P(x)
$$

例如：

```text
A：90%
B：10%
```

A 出现时：

$$
I(A)=-\log_2(0.9)\approx0.152
$$

B 出现时：

$$
I(B)=-\log_2(0.1)\approx3.322
$$

你可以理解成：

```text
A：
“果然是 A。”
→ 没什么意外

B：
“居然是 B！”
→ 信息量很大
```

但是 A 发生得非常多，B 发生得非常少。

所以平均信息量：

$$
H=0.9\times0.152+0.1\times3.322
$$

得到：

$$
H\approx0.469\text{ bit}
$$

所以：

> **熵就是“平均一次结果包含多少信息”。**

#### 5. 现实生活：天气预报

假设某个地方明天下雨的概率：

```text
晴：90%
雨：10%
```

你问天气预报：

> “明天下雨吗？”

其实你已经大概知道：

```text
大概率晴天
```

所以这个问题的信息量不大。

如果换成：

```text
晴：50%
雨：50%
```

那么你真的不知道。

所以：

```text
天气非常确定
    ↓
熵低

天气非常不确定
    ↓
熵高
```

#### 6. 现实生活：交通灯

假设一个路口：

```text
红灯：33%
黄灯：33%
绿灯：34%
```

你无法预测下一次是什么。

熵比较高。

但是如果某个交通灯因为故障：

```text
红灯：100%
```

那么：

```text
熵 = 0
```

因为你完全知道下一次是什么。

#### 7. 现实生活：扑克牌

一副洗得非常随机的 52 张牌。

你问：

> 下一张是什么？

可能是：

```text
黑桃 A
红桃 7
梅花 K
……
```

可能性很多。

所以不确定性很高。

如果我告诉你：

> “牌堆里只剩一张牌，而且是黑桃 A。”

那么：

```text
黑桃 A：100%
```

熵：

$$
H=0
$$

#### 8. 计算机例子：压缩

这就回到我们刚才讲的 ZIP / LZ77 / Huffman。

假设一个文件里面：

```text
A A A A A A A A A B
```

统计：

```text
A = 90%
B = 10%
```

它的熵：

$$
H\approx0.469\text{ bit/字符}
$$

而不是 1 bit。

为什么？

因为数据非常有规律：

```text
AAAAAAAAA...
```

你看到前面几个 A 之后，基本就知道后面还是 A。

所以：

> **数据越有规律 → 不确定性越低 → 熵越低 → 越容易压缩。**

#### 9. 反过来：真正随机的数据

比如：

```text
010011010110101001101011...
```

如果：

```text
0：50%
1：50%
```

那么：

$$
H=1\text{ bit}
$$

这已经达到二进制数据的理论最大熵。

所以：

> **随机数据很难压缩。**

这也是为什么：

```text
随机数据
    ↓
压缩
    ↓
通常几乎没效果
```

甚至可能：

```text
压缩后反而更大
```

因为压缩格式本身还需要保存一些元数据。

#### 10. 这解释了一个很有意思的现象

假设：

```text
AAAAAAAAAAAAAAAAAAAAAAAAAAAA
```

非常容易压缩。

但是：

```text
7f3a91c82d...
```

如果后者是真正随机生成的：

```text
压缩率 ≈ 1
```

这也是为什么：

* `.txt` 很容易压缩
* `.csv` 很容易压缩
* 源代码通常很好压缩
* 日志通常很好压缩
* `.jpg` 通常压缩不了多少
* `.mp4` 通常压缩不了多少
* `.zip` 再压缩通常效果很差

因为后面几种通常已经经过压缩，里面的统计冗余已经被消灭了。

#### 11. 计算机例子：网络通信

假设一个系统返回：

```text
status=success
status=success
status=success
status=success
status=success
status=error
```

如果：

```text
success：99%
error：1%
```

那么信息熵很低。

这意味着：

> 可以使用很少的平均 bit 来描述这些状态。

但如果：

```text
success：50%
error：50%
```

不确定性就高很多。

#### 12. 计算机例子：数据库

假设一个数据库字段：

```text
gender
```

有：

```text
A：50%
B：50%
```

熵比较高。

但是一个状态字段：

```text
status
```

99.99% 都是：

```text
ACTIVE
```

只有极少数：

```text
DELETED
```

那么这个字段的熵非常低。

从信息论角度：

> 大量重复的 `ACTIVE` 没有携带太多新信息。

这也是各种：

* 压缩
* 编码
* 字典
* Bitmap
* Run-Length Encoding

能够发挥作用的原因之一。

#### 13. 计算机例子：日志

比如：

```text
2026-09-23 INFO request success
2026-09-23 INFO request success
2026-09-23 INFO request success
2026-09-23 INFO request success
...
```

你会发现大量内容重复：

```text
2026-09-23
INFO
request
success
```

因此日志文件非常适合压缩。

例如：

```text
原始日志
    ↓
LZ77
    ↓
发现大量重复
    ↓
(distance, length)
    ↓
Huffman / Range Coding
    ↓
进一步压缩
```

#### 14. 现实生活中还有一个特别好的例子：语言

假设让你猜一句话：

> “今天晚上我要去 ______”

你可能猜：

```text
吃饭
```

因为中文存在大量上下文规律。

但如果我随机生成：

```text
“今天晚上我要去蓝色苹果七号飞机……”
```

预测就困难很多。

所以：

> **自然语言本身是有大量统计规律的。**

这也是为什么：

* 文本可以压缩
* LLM 可以学习语言
* GPT 可以预测下一个 token

它们背后其实有一个非常有意思的共同点：

> **都在利用数据中的概率分布。**

#### 15. 这和 LLM 其实也有关系

这个联系非常值得你记住。

假设模型看到：

```text
我今天早上吃了一个
```

模型可能预测：

```text
包子：30%
鸡蛋：20%
面包：15%
馒头：10%
...
```

这里其实就是一个概率分布。

如果模型非常确定：

```text
包子：99%
其他：1%
```

那么：

```text
熵低
```

如果：

```text
包子：20%
鸡蛋：20%
面包：20%
馒头：20%
其他：20%
```

那么：

```text
熵高
```

所以：

> **LLM 的预测分布本身就可以计算熵。**

#### 16. 一个非常重要的直觉：熵不是“混乱程度”

很多教材会说：

> 熵 = 混乱程度。

这个说法容易误导。

更准确的是：

> **熵衡量的是随机变量结果的不确定性，或者平均信息量。**

例如：

```text
AAAAAAAAAAAAAAAA
```

看起来很“乱”吗？

一点都不乱。

所以：

```text
熵低
```

而：

```text
010011010101101001011...
```

如果是真随机的：

```text
熵高
```

因此：

```text
规律性强
    ↓
可预测
    ↓
熵低
    ↓
容易压缩

规律性弱
    ↓
难预测
    ↓
熵高
    ↓
难压缩
```
