### 2. [10道系统设计题，这次全是场景设计和开放题，值得收藏](https://mp.weixin.qq.com/s/j6xancgTOjoclNk3jOpQXQ?scene=1)

> 小小面试凶巴巴 java面试题目必背 2026年10月19日 14:05 上海

#### 1. 设计一个秒杀系统

及格线：

前端限流（按钮置灰、验证码）、后端限流（令牌桶）、Redis 缓存库存、MQ 削峰。

加分项：

说清楚完整流程——提前把商品库存加载到 Redis（库存预热）；用户点击秒杀时先校验资格（黑白名单、频率限制），再扣减 Redis 库存（lua 脚本保证原子性）；扣减成功后发送 MQ 消息，异步落单和扣减数据库库存。再补充关键点：数据库库存用乐观锁（CAS）或悲观锁（for update）；订单表做分库分表；静态资源 CDN 加速；秒杀页面静态化。如果能提到防作弊（同一用户限购、设备指纹识别），会显得考虑周全。

> 翻车点：有人说 “用数据库行锁保证库存不超卖”——行锁在高并发下性能很差，应该先用 Redis 做前置过滤。

#### 2. 设计一个短链接系统

及格线：

用哈希算法（MD5、CRC32）将长链接转成短码，存入数据库，访问时 302 重定向到长链接。

加分项：

说清楚几个关键设计——短码生成：用发号器（雪花算法或数据库自增 ID）转 62 进制（0-9a-zA-Z），比哈希更可控，不会碰撞。存储：用 Redis 做缓存（key 为短码，value 为长链接），MySQL 做持久化。重定向用 301 还是 302：301 是永久重定向，浏览器会缓存，减少服务器压力但无法统计点击量；302 是临时重定向，可以统计点击次数。再补充：短链接的过期策略、防攻击（恶意生成大量短链接）、自定义短链接功能。

> 面试官常追问：如果发号器挂了怎么办？答：可以做双机房部署或用 Snowflake 替代。

#### 3. 设计一个 IM 即时通讯系统

及格线：

客户端和服务端通过 WebSocket 保持长连接，消息经服务端转发。

加分项：

说清楚架构分层——接入层（WebSocket 网关集群，负责维持连接和心跳）；逻辑层（消息路由、会话管理、离线存储）；存储层（消息存 MySQL 或 Cassandra，离线消息存 Redis）。再补充关键设计：消息 ID 用全局唯一 ID（雪花算法）；消息可靠性（客户端 ACK 确认，超时重传）；消息顺序性（同一个会话的消息用同一个队列处理）；多端同步（记录 lastMessageId，拉取增量消息）。如果能提到万人群聊的优化（消息扩散写 vs 扩散读），会非常有深度。

> 面试官常追问：怎么保证消息不丢不重？答：不丢靠 ACK + 重传，不重靠客户端去重（用消息 ID）。

#### 4. 设计一个支付系统

及格线：

订单创建→调用支付网关→支付回调→更新订单状态。

加分项：

说清楚几个关键设计——幂等：支付回调用订单号 + 支付流水号做去重；状态机：订单状态（待支付→支付中→支付成功 / 支付失败 / 退款中 / 已退款）用状态模式管理，不允许跳跃变更；对账：每天和支付渠道对账，差异部分人工处理或自动补偿；资金安全：所有金额用分存储（整数），避免浮点数精度问题。再补充：退款走异步流程，审核通过后调用支付渠道退款接口，失败后定时重试。

> 翻车点：有人说 “支付成功直接更新订单状态”——应该先校验签名、验重、记录流水，再更新订单状态。

#### 5. 设计一个评论系统

及格线：

评论表包含帖子 ID、用户 ID、内容、时间，按帖子 ID 查询。

加分项：

说清楚几个难点——评论排序：按时间倒序（最新评论在前）或按热度排序（点赞数 + 回复数加权）；评论分页：用游标分页（cursor based）代替 offset 分页，避免深度分页性能问题；评论计数：用 Redis 缓存每个帖子的评论数，异步同步到数据库。再补充：楼中楼设计（两级评论还是无限层级？一般两级就够了，无限层级对产品价值不大但复杂度飙升）；敏感词过滤（用 DFA 算法或第三方接口）；删除评论的处理（逻辑删除，保留子评论）。

> 面试官常追问：热评怎么计算的？答：可以按点赞数 + 回复数 + 时间衰减因子综合评分，定时任务重新计算。

#### 6. 设计一个 Feed 流系统

及格线：

用户发动态后，粉丝刷新时看到最新的动态列表。

加分项：

说清楚两种主流方案——推模式（写扩散）：用户发动态后，写入所有粉丝的收件箱（Feed 表），读时直接查收件箱。适合粉丝少的场景。拉模式（读扩散）：用户发动态后只写入自己的发件箱，粉丝刷新时拉取所有关注者的动态再合并排序。适合大 V 场景。实际中常用推拉结合：普通用户用推模式，大 V 用拉模式（粉丝上线时拉取）。再补充 Feed 的排序：按时间倒序或按热度排序；Feed 的缓存：收件箱用 Redis 的 List 或 SortedSet 存储。

> 面试官常追问：推模式下粉丝很多怎么办？答：异步批量写入，或者只推送给在线用户，离线用户上线时拉取。

#### 7. 设计一个打车系统

及格线：

乘客发单→系统匹配附近司机→司机接单→行程开始→行程结束→支付。

加分项：

说清楚几个关键设计——司机定位上报：每隔几秒上报经纬度到 Redis GEO（地理位置数据结构）；乘客发单后，用 Redis GEO 搜索附近司机（半径 3 公里内）；派单策略：距离最近优先、评分最高优先、或抢单模式。再补充：订单状态的分布式事务（乘客发单、司机接单、行程开始、行程结束，每个状态变更都要保证一致性）；价格计算（起步价 + 里程费 + 时长费 + 动态调价）；防刷单（轨迹偏差检测、异常订单识别）。

> 面试官常追问：高峰期怎么动态调价？答：根据供需比（附近订单数 / 附近空车数）动态调整倍率，引导供需平衡。

#### 8. 设计一个日志采集系统

及格线：

应用打印日志到文件，Filebeat 采集，送到 Logstash 处理，最后存到 Elasticsearch，Kibana 展示。

加分项：

说清楚完整链路和优化点——日志采集端：用 Logback 的异步 Appender 避免日志影响业务性能，日志格式统一（JSON 格式便于解析），加 traceId 做链路追踪。传输层：用 Kafka 做缓冲，应对日志峰值流量，Logstash 从 Kafka 消费。存储层：ES 按天建索引，冷热数据分离（热节点 SSD，冷节点机械硬盘），设置索引生命周期管理（ILM），定期删除过期索引。再补充：日志级别动态调整（通过配置中心实时修改线上日志级别，排查问题时临时开 DEBUG）。

> 翻车点：有人说 “日志直接打到 ES”——高峰时期 ES 扛不住，中间必须加消息队列缓冲。

#### 9. 设计一个配置中心

及格线：

配置存储在服务端，客户端启动时拉取配置，支持配置变更后动态刷新。

加分项：

说清楚几个关键设计——配置存储：用数据库持久化，Redis 做缓存加速读取；客户端拉取：启动时全量拉取，运行中通过长轮询（long polling）监听配置变更，变更后增量推送；配置隔离：按环境（dev/test/prod）、按应用、按集群隔离；配置版本管理：每次修改生成新版本，支持回滚；配置热加载：Java 中通过 EnvironmentChangedEvent 或 @RefreshScope 实现 Bean 属性的动态刷新。如果能提到 Apollo 或 Nacos 的设计思路（命名空间、集群、配置项的三级划分），会非常加分。

> 面试官常追问：长轮询和 WebSocket 有什么区别？答：长轮询是客户端发起请求，服务端 hold 住直到有变更或超时返回；WebSocket 是双向通信，服务端可以主动推送。

#### 10. 设计一个短消息（短信）发送系统

及格线：

业务系统调用短信接口，短信服务调用第三方短信通道发送，记录发送结果。

加分项：

说清楚几个关键设计——通道管理：对接多个短信通道（阿里云、腾讯云、AWS SNS），做负载均衡和故障切换；发送策略：重要短信（验证码）走高优先级通道，营销短信走低价通道；限流：每个手机号每分钟最多发几条，每天最多发几条，防止被刷；重试机制：发送失败后按指数退避重试（1 分钟、5 分钟、15 分钟、1 小时），超过最大重试次数后人工介入。再补充：短信内容的模板化管理（避免拼接 SQL 注入和内容合规问题），发送记录的统计分析（成功率、到达率、响应时间）。

> 面试官常追问：怎么保证短信不重复发送？答：业务方传唯一 ID，短信服务端做幂等，同一个 ID 只发一次。

### 3. [实现财富自由的4种方式（自存）](https://mp.weixin.qq.com/s/LtLHK6Mrn0UtRUqMcBrG_Q)

> 颗青梨 随月尝云 2026年11月6日 18:38 四川

真正值得长期追求的财富能力，是让自己的时间、知识、资本和系统能持续创造价值。

很多人把财富自由想得很玄：要么中彩票，要么遇上风口创业暴富（投胎就注定了财富自由的我们不纳入计算）。
但其实所有实现财富自由的人，本质上都用上了同一种东西：杠杆。

杠杆就是让你的产出不再跟时间线性绑定的工具。一份时间换一份钱，到不了自由彼岸；你得让一份时间卖出很多次，或者让别人的时间、别人的钱替你干活。

下面这四种财富杠杆，我按"普通人可触达程度"从高到低排，你可以对号入座。

#### 第一种：复制杠杆，一套工具/内容替你24小时赚钱

这是普通人最容易摸到的杠杆，也是纳瓦尔最推崇的"零边际成本杠杆"。
你写一本书、录一套课、做一个模板、开发一个小工具、运营一个自媒体账号...
这些东西一旦做出来，复制给一万个人和复制给一个人的成本几乎一样。
度假/休息/睡觉的时候，它还可以自己跑数据。

**《纳瓦尔宝典》里说得很直白："财富就是你在睡觉时也能赚钱的资产。" 复制杠杆的本质，就是把你的时间"资产化"，做一次，卖无数次。**

怎么做呢？把你已有的技能或经验，打包成可重复交付的产品。
比如用AI做一个能让某个具体工作高效化的skill，（little red book）上发帖、上架售卖。

#### 第二种：知识杠杆，把你的专长变成可规模化交付的内容

知识杠杆和复制杠杆很像，但更强调"你独有的东西"。
不是"你知道什么"，而是"你能把什么变成别人愿意付费的产品"。 很多人学了一堆东西但没赚到钱，因为他们拥有的是信息，不是可交易的能力。

怎么做呢？找到你的"特定知识"——那些你做起来像玩、别人觉得是苦工的事。 然后把它产品化：课程、咨询、社群、付费专栏，都行。
关键在于别追求"全"，追求"稀缺"。一个细分领域里最懂的人，比什么都懂一点的人值钱得多。

#### 第三种：资本杠杆, 让钱替你生钱

这是最"性感"但也最冷的一条路。钱生钱的前提是...你得先有钱，还得有判断力。
最常见的方式就是投资。

它和劳动收入最大的区别在于：钱不需要每天亲自上班，也有机会产生收益。
这里有一个前提：资本杠杆需要本金，也需要对风险有足够清醒的认识。
普通人可以先从积累本金、学习资产配置和控制风险开始。

第四种：劳动力杠杆，搭建系统让别人帮你创造价值
这是最古老的杠杆，也是门槛最高的一条。你从"自己干活"变成"组织一群人干活"，收入上限被彻底打开，让其他人的时间和能力参与到你的收入创造中。

比如开店或经营一家公司，老板不需要亲自完成每一笔销售、每一次打包和每一项售后，而是通过招聘员工、明确分工和建立管理流程，让团队共同完成经营。

当你已经跑通一个可复制的商业模式（比如前面三种杠杆中的某一种），就可以雇人、外包、建团队，把执行部分交给别人，你负责方向和系统。
不过管理人是世界上最难的事之一。连自己都管不好的人，先别急着管别人。

### 4. [毛选：用人的核心不是能力，是这一条](https://mp.weixin.qq.com/s/Yj75uUqWo03XwKyXj0dD8A)

> 叶成十三 深思悦读 2026年11月7日 00:02 四川

用人用的不只是能力。教员最看重的，是德，和一条心。

你可能遇到过这样的人。

招进来的时候简历漂亮，能力也确实强，三个月以后，处处跟你拧着来。或者你一手带出来的骨干，本事学到了，转身就走，还带走了两个人。

能力都没问题，问题出在别处。

普通人选人，先看简历上写着什么本事。 **高手选人，先看这个人靠不靠得住，跟不跟你一条心。**

**教员说，“领导者的责任，归结起来，主要地是出主意、用干部两件事。”**

用人这件事，他讲得很细，我把它拆成三层。

#### 01 看人先看德，再看才

教员给干部定过一条标准。

> “共产党的干部政策，应是以能否坚决地执行党的路线，服从党的纪律，和群众有密切的联系，有独立的工作能力，积极肯干，不谋私利为标准，这就是任人唯贤的路线。”

你数一数，这么多条里，讲能力的只有有独立的工作能力这一条。其余的，讲的都是这个人的品行和方向。

怎么看出一个人的品行？“不但要看干部的一时一事，而且要看干部的全部历史和全部工作，这是识别干部的主要方法。”

反面的教训，他也点了名。

**“过去张国焘的干部政策与此相反，实行任人唯亲，拉拢私党，组织小派别，结果叛党而去，这是一个大教训。”**

为什么品行要放在能力前面一起看。

1998 年，心理学家施密特和亨特把八十多年来关于招聘选拔的研究汇总在一起，做了一次大规模的元分析。

他们发现，单看一项，能力测验最能预测一个人日后的工作表现。可在能力测验之外再加一项，诚信测验让预测准确度提升得最多。

能力决定一个人能干多少，品行决定他靠不靠得住，两样合起来看，才看得准。能力可以慢慢培养，品行很难临时补上。

#### 02 能力再强，不跟你一条心也没用

选对了人，还得让人往一处使劲。

一百多年前，法国农业工程师林格尔曼做过一个拔河实验。他让人一个一个单独拉绳子，再让几个人一起拉，测每个人用了多大的力。结果人越多，平均每个人使出来的劲越小。

1979 年，心理学家拉塔内和同事用鼓掌、喊叫重做了类似的实验，结果差不多，他们把这叫作社会惰化。

人多，不等于力气就大。心不往一处想，劲就不往一处使，每个人都在等别人多出一点力。

教员讲一条心，讲的是共同的目标。

1944 年 9 月，他在张思德的追悼会上讲了《为人民服务》。

“我们都是来自五湖四海，为了一个共同的革命目标，走到一起来了。” 来路各不相同，目标是同一个。

他在 1938 年定的那条干部标准里，排在第一的，也是能否坚决地执行党的路线。方向一致，排在能力前面。

放到团队里，一个能力很强、心却在别处的人，常常比一个普通但愿意一起干的人更难带。宁可先找愿意一起干的人，再把他带成能干的人。

#### 03 把人当自己人，他才把你的事当成自己的事

人选对了，心也齐了，最后是怎么待人。

1986 年，心理学家艾森伯格和同事提出过一个概念，叫感知组织支持。一个人觉得单位看重他的付出、在乎他过得好不好，就会拿更多的投入来回报。

他们的研究发现，这种感觉越强的员工，缺勤越少，对单位也越上心。

教员讲爱护干部，一口气列了五条办法。

第一条是指导他们，让他们放手工作，使他们敢于负责。

第二条是提高他们，给以学习的机会，教育他们。

第三条是检查他们的工作，帮他们总结经验，发扬成绩，纠正错误。对犯了错误的干部，一般地应采取说服的方法，帮助他们改正错误。

最后一条最见人心。“干部有疾病、生活、家庭等项困难问题者，必须在可能限度内用心给以照顾。”

工作上帮他长本事，生活上帮他渡难关。你把他当自己人，他才会把你的事当成自己的事。

#### 04 三步法，把用人落到地上

道理讲完了，落到手上，分三步。

第一步，招人的时候，把德拆成看得见的标准。

德看不见，可它会留在一个人做过的事里。面试时别只问他会什么，多问几件具体的旧事。

上一份工作出了差错，他是怎么处理的。

离开上一家单位时，手上的活是怎么交接的。

能打听的话，向他以前的同事问一问。

这就是教员说的，看全部历史和全部工作。

第二步，用人的时候，先给机会，别先给位置。

新人进来，先交给他一件实打实的事，让他放手去干。

教员说了放手工作，也说了另一半。“有委托而无检查，及至犯了严重的错误，方才加以注意，不是爱护干部的办法。”

所以事交出去了，过程中要看，做完了要帮他复盘。事办成了，再给位置，位置是对他做成的事的确认。

第三步，留人的时候，把人当自己人处。

给他学东西的机会，让他一年比一年值钱。他犯了错，先关起门来讲道理，别当众给他难堪。

他家里有难处，在你能做到的范围里，搭一把手。

#### 写在最后

**选对了人，事才有人扛。待人像自己人，人才肯留下。用人用到最后，用的是人心。**

如果你最近正为团队里的人发愁，我想对你说，先别急着换人。

今晚想一想，你手下最靠得住的那个人，你上一次问起他的家里事，是什么时候。

明天找个机会，问一句。
